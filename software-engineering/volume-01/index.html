Keep Functions Focused

One clear responsibility

A focused function does one job and makes that job easy to recognize. It is simpler to name, test, and change without surprising the code that calls it.

Keep calculation separate from tasks such as reading files, formatting messages, or saving data. That gives each part a clear reason to change.

Concept

A function is easier to understand when its name, inputs, and result all describe the same small task.

Example

This function calculates a subtotal from a sequence of line totals:

public static decimal CalculateSubtotal(
    IEnumerable<decimal> lineTotals)
{
    return lineTotals.Sum();
}

Remember

One function, one clear responsibility. A useful name should explain what the function returns or changes.

Important

Decide how the function handles empty or invalid input, and make that behavior explicit in its contract.

Short exercise

Write a function that returns the average of a collection of numbers. Give it one responsibility and decide what it should return when the collection is empty.
